\begin{abstract}
AI-assisted coding lowers the cost of producing plausible code but raises the importance of deciding whether a change is safe to merge. Jankurai turns a pull request merge decision into a reproducible, versioned audit artifact. It defines a repository conformance standard for human- and agent-authored changes whose central artifact is the merge witness: a binding among changed paths, owner routing, required proof receipts, observed evidence, score deltas, missing-evidence decisions, tool version, and commit identity.

The paper contributes a stack-neutral, agent-native repository model with owner maps, test maps, generated-zone policy, stable rule identifiers, version manifests, and bounded authority; a conformance mechanism based on proof lanes, audit JSON/Markdown, repair queues, and merge witnesses; and a non-normative reference implementation and reference profile. Conformance is pass/fail against required artifacts. Scores are posture and prioritization signals, not merge approval by themselves.

The claim is deliberately bounded. Jankurai does not prove full program semantics, does not claim final empirical superiority, and does not require its Rust/TypeScript/PostgreSQL reference profile. It is a standards proposal with an early local CLI and a conformance-oriented evaluation path. The thesis is operational: repositories claiming Jankurai conformance need current machine-readable artifacts strong enough to audit the merge decision at merge time.
\end{abstract}
