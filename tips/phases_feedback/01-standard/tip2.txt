## Phase name: **Phase 01 — Standard Stabilization**

I would treat **Phase 01 as not truly implementation-complete yet**, even though the phase file currently says `Status: complete`. The reason is important: the same file says it is a **docs-only execution plan**, not the implementation, and it explicitly names the remaining implementation gaps: incomplete artifact/schema coverage, missing semantic report compatibility guards, doctor/security diagnostics that need to distinguish missing tools from repo defects, current-vs-roadmap doc boundaries, and reusable release evidence conventions. 

The moonshot says the repo must make ownership, proof, generated truth, evidence, and expiring exceptions machine-readable, with the operating loop `intent -> bounded agents -> proof lanes -> evidence -> expired exceptions -> reusable primitives`.  The root README confirms this repo is supposed to be a control plane where ownership, proof, generated zones, and repair evidence are machine-readable, and it names `agent/`, `docs/`, `schemas/`, `crates/jankurai/`, `packages/ux-qa/`, `tips/`, and `reference/` as the key surfaces. ([GitHub][1]) Phase 00 also makes Phase 01 the gate before the rule engine, proof router, init profiles, UX proof, security, contracts, and later repair phases. 

So the best Phase 01 closeout is not “add new moonshot features.” It is to **harden the v0.4 public surface so later phases cannot accidentally drift it**. The patch below does that by:

1. Tightening `schemas/repo-score.schema.json` so it actually requires the fields that the standard and release plan already say are part of the audit contract: `paper_edition`, `target_stack_id`, `target_stack`, `scope`, hard caps, UX/security/boundary readiness, findings, and repair queue. The model already emits these fields today. 
2. Adding a real semantic compatibility guard for JSON, Markdown, SARIF, JUnit, GitHub summary, and repair queue JSONL exports. The current schema test mostly checks schema files parse; it does not prove report output compatibility. 
3. Making `just security` and CI call `jankurai security run`, so security evidence is always written as JSON instead of only running raw shell. The current wrapper emits one envelope step for the script, not per-tool evidence. 
4. Rewriting `tools/security-lane.sh` so it emits per-tool structured evidence lines while still remaining pure Bash and adding no external required tools.
5. Teaching `doctor` to report missing required/advisory security tools as prerequisite status, not as repo-state breakage, while still letting strict mode block where appropriate. The current doctor only emits generic low-severity tool-missing messages. 
6. Adding `docs/artifact-contracts.md`, which is the Phase 01 artifact contract matrix: every machine-readable artifact either points to a schema, a semantic compatibility guard, or a documented exemption.
7. Updating `docs/testing.md`, `docs/release-plan.md`, `docs/README.md`, and `tips/phases/01-standard-stabilization.md` so future agents can tell exactly what is implemented now versus roadmap/later-phase behavior.
8. Avoiding paper and `reference/` changes, in line with Phase 01 constraints. 
9. Avoiding owner/test map changes because the new durable paths are already covered by existing routes: `docs/`, `schemas/`, `crates/jankurai/`, `.github/`, `Justfile`, `tools/`, and `tips/` all already have owner/test-map entries.

+

+## Exemption Policy
+
+The source maps `agent/owner-map.json`, `agent/test-map.json`, `agent/generated-zones.toml`, `agent/proof-lanes.toml`, and `agent/standard-version.toml` are not generated artifacts. They are durable control-plane source files. Phase 01 treats them as source contracts validated by semantic audit behavior and command wiring rather than by newly mandatory schemas. Later phases may add dedicated schemas, but Phase 01 should not block the v0.4 surface on a schema migration that is not required to stabilize the current release.
+
+## Generated Versus Volatile
+
+- Tracked source truth lives under `agent/`, `docs/`, `schemas/`, `crates/`, `packages/`, and other routed source directories.
+- Canonical tracked score evidence remains `agent/repo-score.json` and `agent/repo-score.md`.
+- Volatile proof, security, doctor, UX, migration, and compatibility evidence lives under `target/jankurai/`.
+- Generated outputs must be changed through their producer command, never by hand.
+- Logs are sidecars, not source truth. A log becomes useful only when a JSON receipt points to it.
+
+## Phase 01 Closeout Rule
+
+Phase 01 is complete only when:
+
+1. `schemas/repo-score.schema.json` covers the live public report fields.
+2. JSON, Markdown, SARIF, JUnit, GitHub summary, and repair queue exports have semantic compatibility tests.
+3. `just security` writes `target/jankurai/security/evidence.json`.
+4. `doctor` distinguishes missing optional or non-strict tools from broken repo state.
+5. Release evidence paths are documented here and in `docs/release-plan.md`.
+6. No paper or `reference/` paths are changed.
+
+## Recommended Closeout Commands
+
+```bash
+cargo test -p jankurai
+just compat
+just security
+cargo run -p jankurai -- doctor --fail-on high --json target/jankurai/doctor.json --md target/jankurai/doctor.md
+just fast
+just score
+```
````
