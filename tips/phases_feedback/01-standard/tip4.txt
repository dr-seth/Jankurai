    let repo = repo_root();
    validation::validate_value(&repo, schema, value)
        .unwrap_or_else(|err| panic!("{label} failed schema validation: {err}"));
}

## Purpose

Phase 01 is the v0.4 contract gate. Later phases may add capabilities, but they must not weaken the stable release surface that agents and CI already depend on.

This file separates current behavior from roadmap behavior, names the machine-readable artifact contracts, and defines the release evidence bundle for Phase 01 closeout.

## Current Implemented Contract

The current stable surface includes:

- Rust CLI package under `crates/jankurai/`

- additive schema properties,
- new optional receipt companion paths,
- clearer doctor diagnostics,

Forbidden without migration notes:

- renaming public report fields,
- removing version bindings,
- moving canonical score artifacts,
- adding new mandatory external tools to `just fast`,
- hand-editing generated outputs,
- editing `paper/` from Phase 01.

Phase 02 can rely on stable finding fields and rule IDs.

### Why this is the right Phase 01 finish

This does **not** implement Phase 02–13 features. It makes their contracts safe. Phase 02’s rule engine depends on stable finding IDs and fields; Phase 03’s proof ledger depends on stable receipts and evidence schema; Phase 05/06 need optional but schema-validated UX/security evidence; Phase 07 needs generated-zone and boundary truth to be parseable; Phase 10/12/13 can stay planner/dry-run without Phase 01 overclaiming them. The phase docs themselves show those dependencies and partial statuses across later phases.        

The especially important steering decision is that Phase 01 should be **boring and defensive**: schema registration, compatibility tests, doctor diagnostics, release evidence, and docs boundaries. That matches the moonshot’s “wrong code becomes easier to reject than to rationalize” success criterion.
