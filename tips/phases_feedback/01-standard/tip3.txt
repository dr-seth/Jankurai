## Phase name: **Phase 01 — Standard Stabilization**

I would treat Phase 01 as **not just “more docs”**, but as the release-hardening layer that makes the existing v0.4 surfaces provable. The moonshot says the repo should make it obvious how an agent finds ownership, selects proof, leaves durable evidence, and avoids hidden/generated drift; Phase 01 is the foundation that makes those promises enforceable before later phases add rule engines, proof ledgers, golden repos, UX proof, and repair automation. 

After studying `moonshot.md`, the phase index, `01-standard-stabilization.md`, the Rust audit/report/doctor/security code, schemas, maps, `Justfile`, and CI, my strongest recommendation is: **finish Phase 01 by locking report compatibility, validating the agent artifact surface, routing security evidence through the Rust wrapper, and making doctor distinguish “missing optional tool” from “broken repo contract.”** That directly closes the gaps named in the Phase 01 router: incomplete schema coverage, semantic report compatibility tests, doctor/security lane reality, docs boundary, release evidence conventions, and routing hygiene. 

The repo already has a strong base: report structs include versioning, fingerprints, policy, proof receipts, UX/security/boundary summaries, findings, and repair queue fields; the CLI emits JSON, Markdown, SARIF, JUnit, GitHub summary, and repair queue JSONL; doctor already writes receipts; and `agent/repo-score.json` / `agent/repo-score.md` are declared generated zones.    

Below is a single copy-pasteable implementation script. It does **not** create separate downloadable files. Paste it from the repo root. It writes new schemas, patches schema validation, adds Phase 01 report-compatibility tests, strengthens doctor artifact validation, routes the security lane through `jankurai security run`, updates CI artifact evidence, and adds release-evidence wording.

I could not run this patch in my sandbox because direct cloning failed with DNS resolution for GitHub, so treat the validation section after the script as the commands to run locally.

import json
from pathlib import Path

ROOT = Path(".")


def path(rel: str) -> Path:
    return ROOT / rel


def read(rel: str) -> str:
    return path(rel).read_text()


def write(rel: str, text: str) -> None:
    p = path(rel)
    p.parent.mkdir(parents=True, exist_ok=True)
    p.write_text(text)


def write_json(rel: str, payload: dict) -> None:
    write(rel, json.dumps(payload, indent=2) + "\n")


def replace_once(rel: str, old: str, new: str) -> None:
    text = read(rel)
    if old not in text:
        raise SystemExit(f"Could not find expected text in {rel}:\n{old[:400]}")
    write(rel, text.replace(old, new, 1))


def append_once(rel: str, marker: str, text_to_append: str) -> None:
    text = read(rel)
    if marker in text:
        return
    write(rel, text.rstrip() + "\n\n" + text_to_append.strip() + "\n")

doctor_helpers = r'''
fn check_agent_json_schema(
    repo: &Path,
    diagnostics: &mut Vec<Diagnostic>,
    rel_path: &str,
    schema: ArtifactSchema,
    check_read: &str,
    check_json: &str,
    check_schema: &str,
) {
    let path = repo.join(rel_path);
    if !path.is_file() {
        return;
    }
    let Ok(text) = fs::read_to_string(&path) else {
        diagnostics.push(Diagnostic {
            check_id: check_read.into(),
            severity: "medium".into(),
            path: rel_path.into(),
            message: "could not read agent artifact JSON".into(),
        });
        return;
    };
    let Ok(value) = serde_json::from_str::<serde_json::Value>(&text) else {
        diagnostics.push(Diagnostic {
            check_id: check_json.into(),
            severity: "medium".into(),
            path: rel_path.into(),
            message: "agent artifact is not valid JSON".into(),
        });
        return;
    };
    if let Err(err) = validation::validate_value(repo, schema, &value) {
        diagnostics.push(Diagnostic {
            check_id: check_schema.into(),
            severity: "medium".into(),
            path: rel_path.into(),
            message: format!("agent artifact failed schema validation: {err}"),
        });
    }
}

fn check_agent_toml_schema(
    repo: &Path,

    schema: ArtifactSchema,
    check_read: &str,

### What this patch intentionally changes

It adds schema coverage for the agent artifact surface that Phase 01 depends on: `owner-map`, `test-map`, `generated-zones`, `proof-lanes`, and `standard-version`. The existing validator already validates JSON outputs and some TOML policy files; this patch extends it so doctor can validate the core maps and manifests that later phases rely on. That directly supports the moonshot requirement that changed paths map to ownership and proof, generated outputs have declared sources/commands, and evidence is machine-readable. :contentReference[oaicite:6]{index=6}

It hardens `schemas/repo-score.schema.json` so the schema actually reflects the v0.4 public report contract already emitted by `model::Report`: `paper_edition`, `target_stack_id`, `target_stack`, `repo`, `scope`, `caps_applied`, `hard_rules`, `ux_qa`, `security_evidence`, and `boundaries`. Those fields are already in the Rust report model; Phase 01 should make their presence test-protected rather than accidental. :contentReference[oaicite:7]{index=7}

It adds `crates/jankurai/tests/phase01_report_compatibility.rs`, which is the missing semantic compatibility guard. The tests protect JSON shape, Markdown sections, SARIF, JUnit, issue JSONL, and repair queue JSONL. That is the most important Phase 01 guard because the CLI already exposes all of those outputs. :contentReference[oaicite:8]{index=8}

It changes `just security` and the GitHub workflow security step to run through `jankurai security run`, not directly through `bash tools/security-lane.sh`. The script remains the canonical shell entrypoint, but the Rust wrapper now produces structured evidence JSON and a log under `target/jankurai/security/`, which is exactly the evidence convention the docs already describe. :contentReference[oaicite:9]{index=9} :contentReference[oaicite:10]{index=10}

It improves `doctor` by validating the key source manifests, checking `agent/audit-policy.toml`, and keeping missing security tools as low-severity advisory diagnostics outside strict mode. Doctor already writes receipts under `target/jankurai/receipts/`, so this patch makes those receipts more meaningful without turning optional local tools into false repo failures. :contentReference[oaicite:11]{index=11}

### Why this gets Phase 01 to “100%”

This is the stabilization layer later phases need. Phase 02 can introduce a richer rule engine only after report and finding contracts are stable. Phase 03 can add proof routing and evidence ledgers only after receipts, evidence paths, and source-vs-generated boundaries are stable. Phase 05/06 can attach UX/security proof only after Phase 01 makes “missing optional local tool” visibly different from “repo cannot prove itself.” The phase index explicitly makes Phase 01 the gate for report compatibility and v0.4 release readiness, and the Phase 01 plan calls out exactly these workstreams.  

The key steering principle is: **do not add moonshot behavior here; make the existing release surface impossible to accidentally break.** This patch keeps `just fast` free of new required third-party tools, does not touch `paper/`, does not move canonical score artifacts, does not rename public report fields, and does not hand-edit generated score outputs. It turns Phase 01 from “the plan says stabilize” into “the repo proves stabilization with schemas, tests, doctor diagnostics, and release evidence.”
